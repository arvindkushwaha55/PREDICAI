# PREDICAI — Development Log

## 13 November 2026 — Design to working system in one day

**Morning — research & foundations**
- Research report (20 points) and a 12-part plan with honesty rules:
  RUL in cycles only, no fabricated metrics, synthetic data always
  flagged, simulated ≠ real, thresholds are policy not science.
- FD001 downloaded from NASA and verified exactly (train 20,631 rows /
  100 engines; test 13,096 / 100; RUL file 100 values).
- EDA findings that shaped everything: 0 missing values; 6 sensors
  exactly constant; no engine shorter than the 30-cycle window.
- Preprocessing contract frozen: 14 sensors (6 constant + near-constant
  sensor_6 dropped), RUL cap 125, engine-wise 80/20 split (seed 42),
  scaler fit on train only. Windows: train 14,459 / val 3,272 / test 100.
- Maintenance module (SQLite + policy recommendations) built and tested
  in parallel; synthetic seed data flagged `is_synthetic=1`.
- Training code + Kaggle notebook prepared; the OWNER trains the model
  himself on Kaggle (project decision).

**Evening — the owner's Kaggle run + everything it unlocked**
- Kaggle run: training + evaluation succeeded; the ONNX cell failed on
  Kaggle with `ModuleNotFoundError: onnxscript` (torch ≥ 2.9's new
  default exporter needs it). Root-caused and fixed in the notebook
  (legacy exporter, `dynamo=False`).
- Returned artifacts verified independently BEFORE any claim:
  test metrics recomputed from the raw predictions file matched
  `metrics.json` exactly (**RMSE 13.73 / MAE 9.89 / NASA 431.3**);
  Kaggle's `preprocessing.json` was byte-identical to the local one.
- ONNX exported locally from `best_model.pt`; PyTorch ↔ ONNX parity
  1.53e-05. A local copy of the weights reproduced Kaggle's predictions
  to 0.000168 (proof the .pt is the model behind the metrics).
- Rust edge API: `ort` pinned to `=2.0.0-rc.15` (no stable 2.0 exists),
  `load-dynamic` against the Python wheel's runtime library after the
  vendor CDN refused this machine. First parity attempt was 5e-3 off —
  traced to raw inputs being cast to f32 before normalization; fixed by
  keeping f64 through the z-score math (plan rule), after which the
  Rust API's engine-1 prediction matched Kaggle's PyTorch output to
  5 decimal places (117.60932). Cargo suite 15/15 incl. the real
  parity test with Python-generated fixtures.
- Explainability: permutation importance (baseline reproduced the
  reported val RMSE to 0.000002) + hand-implemented Integrated
  Gradients (completeness error 0.0115%). The two rankings only
  moderately agree (ρ = 0.56) — documented, not hidden.
- Simulator: FD001 test engines 1 / 49 / 100 replayed through the live
  Rust API — 445 predictions logged, finals match Kaggle to ≤0.00002.
  (Data correction made en route: engine 1 has only 31 test cycles;
  engine 49 is the 303-cycle one.)
- Dashboard (React/TypeScript): fleet / machine / maintenance /
  model-info views over a verified data export; live panel talks to the
  real API through the dev proxy (the API sends no CORS headers — found,
  worked around, documented). Maintenance tables turned out empty in
  both databases, so the demo records are generated by the maintenance
  module's own seed function at export time and disclosed as synthetic
  in the UI.
- Repository created on GitHub as **PREDICAI, Private**, and the full
  source delivered through the web UI in verified batches (the GitHub
  App route could not see the new repo; local git push had no
  credentials in the build VM).
