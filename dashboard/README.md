# PREDICAI Dashboard (Part 11 / Phase F)

React + TypeScript + Vite + Tailwind CSS v4 + Recharts. Single page, four
views (sidebar switching, no router): **Fleet Overview · Machine Detail ·
Maintenance · Model Info & Live API**.

All RUL values are in **cycles** — never hours. Every panel labels its data
source. Nothing on any page is placeholder or invented data.

## Run it

```bash
cd dashboard
npm install
npm run dev        # http://localhost:5173
```

Regenerate the bundled data first if the underlying artifacts changed:

```bash
../.venv/bin/python data_export.py   # writes src/data/demo_data.json
```

Production build (type-checks strictly, then bundles):

```bash
npm run build      # tsc -b && vite build  ->  dist/
```

## Live API panel (Model Info view)

The "Run live prediction" button and the API status pill talk to the Rust
edge API. Requirements:

1. The edge server running on **port 18080** with the ONNX runtime library
   path set (from the repo root; see `edge/` and `simulator/README.md`):

   ```bash
   cd edge
   ORT_DYLIB_PATH=<path-to>/libonnxruntime.so.1.32.0 PREDICAI_PORT=18080 cargo run
   ```

   (`libonnxruntime.so.1.32.0` currently comes from the project venv:
   `.venv/lib/python3.12/site-packages/onnxruntime/capi/`.)
2. The dashboard viewed via **`npm run dev`**. The Rust API sends no CORS
   headers, so a browser cannot call `http://localhost:18080` directly from
   the dashboard's origin. In dev, the app calls the same-origin `/api/*`
   path and `vite.config.ts` proxies it to `localhost:18080`. A statically
   served `dist/` build has no proxy — the panel then honestly shows
   OFFLINE with the reason instead of fake numbers. Set `VITE_API_BASE` to
   override the base URL (default `/api`).

Behaviour: the pill shows CHECKING → LIVE / OFFLINE from a real
`GET /health`; the prediction button stays disabled unless the API is live
**and** reports `model_loaded: true`. A live run POSTs the bundled
ENGINE-001 sample window (30 × 14 raw values) to `/predict_rul` and shows
the returned RUL next to the parity-fixture expectation (≈ 117.61 cycles).
The API also records the prediction in its own predictions log
(`maintenance/predicai.db` by default).

Verified end-to-end on 13 Nov 2026 through the dev proxy: `/api/health`
returned the real API payload and the sample POST returned
`117.60932 cycles` — matching the Rust parity fixture to 5 decimal places.

## Data provenance

`src/data/demo_data.json` is generated by `data_export.py` from:

| Section | Source | Label shown in UI |
|---|---|---|
| Replay series, finals, stats | `simulator/demo.db` → `predictions_log` (rows written by the Rust API during Part 10 replays of FD001 test engines 1 / 49 / 100) | FD001 REPLAY |
| True RUL per cycle | `ml/data/raw/RUL_FD001.txt` + recorded cycle counts (same definition as preprocessing) | FD001 REPLAY |
| Maintenance records + recommendation | Part 8 maintenance module itself (`seed_synthetic_demo()` + `make_recommendation()`, throwaway DB — demo.db is opened read-only). FD001 has **no** real service records | SYNTHETIC DEMO DATA banner + per-record flag |
| Model info, metrics, parity, explainability top-5s | `ml/artifacts/model_metadata.json`, `metrics.json`, `explainability.json` (real Kaggle run, 13 Nov 2026) | Real run only |
| Live sample window | `edge/tests/fixtures/parity_windows.json`, engine 1 case | Parity fixture source line |

Notes on honesty choices:

- **Cycle alignment is verified, not assumed**: the export checks that each
  engine's logged prediction count equals recorded cycles − 29 (the
  simulator predicts once per cycle from cycle 30); `end_cycle` is only
  filled when that check passes.
- **Status chips** use the RUL bands of `maintenance/policy.py` v1.0
  (≤ 30 REVIEW, ≤ 50 INSPECTION, else MONITOR). They are *policy thresholds
  for planning reviews, not validated failure boundaries*; the service-age
  escalation is only applied where service history exists (the synthetic
  demo machine) and the UI says so.
- **No sensor panel**: `predictions_log` stores predictions only, so no
  per-cycle sensor series exists to chart. The Machine view shows
  prediction data and says exactly this instead of reconstructing series.
- **Sensor importance = association, not causation** — the Model Info view
  carries the Part 6 honesty note verbatim.
- ENGINE-001's test life is only 31 recorded cycles, so its replay has
  exactly 2 predictions; the chart shows those 2 points un-interpolated and
  the view explains why.
